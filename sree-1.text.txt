Amazon GuardDuty is AWS's threat detection service. It continuously monitors your AWS environment for malicious activity, and specifically for S3 it has a Malware Protection feature: when a new object lands in a monitored bucket, GuardDuty automatically scans it for malware and emits a scan-result event — without you needing to run your own antivirus infrastructure.

Here's how your diagram's flow works, step by step:

	1.	User / MuleSoft / Future Apps → Landing Bucket: Files are uploaded into an S3 "Landing Bucket," either directly by a user or via MuleSoft (and other apps in the future).
	2.	Landing Bucket → GuardDuty ("Put Event"): The upload triggers an event that GuardDuty picks up to scan the object for malware.
	3.	GuardDuty → EventBridge ("Scan Results"): Once scanning finishes, GuardDuty sends the scan result (clean/infected) to EventBridge.
	4.	GuardDuty → Cloudwatch: GuardDuty findings also flow to CloudWatch for monitoring/logging.
	5.	EventBridge → Lambda ("Trigger"): Based on the scan result, EventBridge triggers a Lambda function to act on the file.
	6.	Lambda → Landing Bucket ("Delete scanned files"): That Lambda deletes the original file from the Landing Bucket now that it's been processed.
	7.	Lambda ("Copy files to respective bucket"): The same/related Lambda logic copies the file into the correct downstream bucket depending on the result:
	•	Un-Processed – files not yet scanned/handled
	•	Quarantine Bucket – files flagged as malicious
	•	Clean Object Bucket – files confirmed clean
	8.	Downstream Lambdas per bucket:
	•	Un-Processed → Notification to BAU (business-as-usual team alerted)
	•	Quarantine Bucket → Notification to SecOps (security team alerted about malware)
	•	Clean Object Bucket → API call to MuleSoft (clean file gets passed back into MuleSoft for normal processing) → feeds into a MuleSoft downstream box
	9.	KMS: Sits alongside for encryption/decryption of objects in these buckets (key management for data at rest).
	10.	Cloudwatch → AWS Firehose → Splunk: Logs/events get streamed via Firehose into Splunk for centralized logging and analysis.
	11.	Splunk → ServiceNow: Splunk can raise incidents/tickets in ServiceNow.
	12.	ServiceNow → SecOps Team / BAU Team: Tickets get routed to the two teams for action.

In short: it's an automated malware-scanning pipeline — GuardDuty scans every file landing in S3, clean files get routed back into the business flow (via MuleSoft), infected files get quarantined and SecOps gets alerted, and everything is logged through CloudWatch → Firehose → Splunk → ServiceNow for visibility and incident tracking.
